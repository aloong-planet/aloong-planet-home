## Question
Does the link back to the homepage read right in the header of each app website (Transfer, Agentshed, JustSnap), in Chinese and in English, on wide windows and on phones?

## Structure basis
The user chose a breadcrumb at the far left of each app website's header, "aloong planet / <app name>": "aloong planet" opens the homepage in the current tab, and the app name keeps its existing link to the top of its own page. The wording is the same on Chinese and English pages. Each header is drawn from the live website as it is: its height, brand (with its icon where it has one), navigation, language toggle and the narrow-window rule that hides the navigation. The breadcrumb puts "aloong planet" and a "/" before the existing brand, in the size and grey of that website's navigation links, with the same hover colour as those links. JustSnap draws a focus ring on its header links, and the homepage link gets the same ring. On windows 400px wide or narrower, the breadcrumb does not fit on one line beside the language toggle, so "aloong planet /" goes small above the app name, within the same header height.

The hero under each header is the context, cut to its top: its copy is the live copy, and JustSnap's screenshot is an empty frame of the same size and look.

## Demo scaffolding
Not part of the design; do not implement. The page stacks the six first screens (three websites, Chinese then English) on a grey sheet and cuts each to a fixed height. "aloong planet" opens the homepage prototype; every other link is drawn and leads nowhere.

## Uncovered dimensions
- Only the light appearance is drawn. All three websites follow the visitor's system appearance; the breadcrumb takes each website's navigation-link grey, which each website already declares for dark.
- The rest of each page below the first screen is not drawn.
